# PLINK2 validation inputs

This collection combines one unchanged public experimental genotype fixture
with explicitly synthetic regression inputs. It tests the original PLINK2
program across native and WebAssembly execution. The synthetic phenotypes,
covariates and scoring coefficients have no biological or clinical meaning.
No expected scientific output is generated by this fixture script.

## Authentic 1000 Genomes input

`plink2/real/1kg-phase3-chr21.vcf.gz` is copied byte for byte from
[`chrchang/plink-ng`](https://github.com/chrchang/plink-ng/tree/72119068234ce0acf7189e53dfe67a527bc53e2c/2.0/Tests/TEST_PHASED_VCF)
at commit `72119068234ce0acf7189e53dfe67a527bc53e2c`. Upstream documents it as
the original header and first 600 biallelic records from the official 1000
Genomes Phase 3 release, after excluding MULTI_ALLELIC records. The VCF header
identifies the 1000GenomesPhase3Pipeline, file date 20150218 and GRCh37/hs37d5
reference. It contains 2,504 unchanged public sample IDs and 600 phased GT
records on chromosome 21, positions 9,411,239 through 9,425,829. There are no
missing genotypes, multiallelic variants or dosage fields in this fixture.
The 78,046-byte gzip has SHA-256
`db71978e9bc08df06ef798256cff6781f4f1bf9788b38dd22a94b987da67ea73`.

`real/keep48.samples.txt` names the first 48 samples in their original order,
to keep pairwise matrix tests small. This is an explicit computational test
subset, not a representative population sample. `real/scores.tsv` selects
the 20 variants with greatest ALT counts (source order breaks ties) and
assigns the arbitrary coefficient `((rank % 7)-3)/8`, with zero-based rank.
These are synthetic software-test coefficients, not measured effect sizes or
a polygenic risk score. The authentic genotype file is unchanged.

## Synthetic inputs

All paths below start with `plink2/synthetic/`.

| Input | Coverage and origin |
|---|---|
| `glm-missing/input.vcf` | 603 fictional samples and 30 biallelic variants. Retains the upstream TEST_GLM_LOGISTIC_MISSING pattern: alternating no-missing and 1/2/6/9/14 missing calls, including non-vector-aligned sample counts. |
| `glm-missing/covariates.tsv` | Two fictional quantitative covariates, C1 and C2. |
| `glm-missing/phenotypes.tsv` | BINARY is independent case/control status, QUANT is an independent quantitative label, and FIRTH intentionally assigns case status to v1 ALT carriers to create separation. All are synthetic. |
| `score-hardcall/` | 203 fictional samples, 40 rare/common hardcall variants, missing calls, and two arbitrary coefficient columns. Adapted from TEST_SCORE_CENTER_MISSING. |
| `score-dosage/` | The same upstream test design with GT:DS, perturbations to some dosages, chrY/MT haploid calls and missing data. `sex.tsv` explicitly makes these fictional samples male. |
| `multiallelic.vcf` | Unchanged two-record/four-sample VCF here-document from TEST_VCF_MULTIALLELIC_DS_FIELDS, including ALT2/ALT3 and missing calls. |
| `haploid.vcf`, `haploid.psam` | Unchanged three-record/four-sample VCF here-document and sex-table contents from TEST_BCF_HAPLOID_HDS; includes GT:DS:HDS on Y/MT. |
| `phased-multiallelic.vcf` | Upstream TEST_MULTIALLELIC_PHASED_R first generator: 400 fictional samples, eight variants, two chromosomes, dense/sparse multiallelic phased patterns, and up to 20 alleles. Variant/genotype records follow the original generator exactly; contig length metadata is set to 100000000. |
| `multinomial/` | Unchanged committed upstream TEST_GLM_MULTINOMIAL inputs: `mn.vcf.gz`, `mn_multi.vcf.gz`, `pheno.txt`, `covar.txt`, and `sex.txt`. These were generated upstream; they are not an authentic cohort. The original generator is retained for attribution. |

The missingness and score adaptations use the explicit linear congruential
generator already used by the upstream phased-multiallelic regression:
`state = (1103515245*state + 12345) % 2147483648`, `U = state/2147483648`.
This replaces implementation-dependent AWK `rand()` and PLINK `--dummy` in
the adapted inputs, allowing Python-only byte-reproducible regeneration.
It deliberately does **not** claim that adapted random values match an
upstream AWK implementation or PLINK's pseudorandom stream.

For the 603-sample regression, genotype frequencies are `0.12+0.36*U` with
seed 3, then each genotype is two Bernoulli allele draws. Missingness uses
the exact upstream modular sample permutation. Covariates use upstream
formulas `U-0.5` and `3*U` with seed 7; BINARY uses `U<0.4` with seed 11.
QUANT is `4*U-2` from an independent seed 19. FIRTH is exactly 2 for any
v1 ALT carrier and 1 otherwise. The separation test is intentionally
constructed to exercise Firth behavior, not to demonstrate a real association.

Score fixtures retain the upstream 203-sample/40-variant design, rare/common
frequencies, eight-percent missingness probability, dosage perturbation and
haploid rules with seeds 17/18. Coefficients follow the original two-column
formulas with seed 5. The first 12 variants use ALT coefficients; later
variants alternate ALT and REF. Header lines are supplied explicitly.

## Provenance and reuse

`provenance/sources.lock.json` pins each upstream source file by repository
commit, URL, byte count and SHA-256. Original source bytes are cached in
`build/plink2-sources/`. `provenance/upstream/` retains original regression
recipes; `provenance/fixture-sources.json` records each transformation.
`provenance/PLINK2-COPYING` retains the GPLv3 license for the upstream
regression code. PLINK2 application code and adapted upstream recipes are
GPL-3.0-or-later; genomic data reuse is described separately in
`provenance/DATA_REUSE.md`. No blanket Creative Commons license is asserted
for these biological records.

The manifest inventories all included data, provenance and README files,
records measured VCF coverage, and binds the exact regeneration script.
Native PLINK2 computes scientific results during validation. This fixture
contains no handwritten PLINK2 result goldens.

## Verification and regeneration

From the repository root:

```sh
python3 scripts/fetch-plink2-test-data.py --verify
python3 scripts/fetch-plink2-test-data.py --fetch
python3 scripts/fetch-plink2-test-data.py --regenerate
```

Verification is offline and requires Python 3.11+. Fetching checks every
source against its frozen byte count and checksum. Regeneration reproduces a
fresh tree and compares it to the frozen manifest; it never changes expected
hashes. Only the explicit maintenance command
`--regenerate --update-manifest` replaces files and the manifest. CI must
not use that option.

Passing these small tests establishes the tested output behavior, not
biobank-scale performance, representative ancestry inference or clinical
interpretation. VCF import in PLINK2 preserves only supported genotype,
phase and dosage information; general lossless preservation of every VCF
FORMAT field is not claimed.
