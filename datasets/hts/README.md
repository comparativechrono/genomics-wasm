# HTS scientific fixtures

These inputs validate matched bcftools, HTSlib and SAMtools 1.16 and 1.21. They
are not clinical cases and carry no assertion about real individuals.

`common/` is explicitly synthetic. `scripts/fetch-hts-test-data.py` generates
these inputs deterministically, including four-sample VCFs with mixed ploidy,
missing and half-missing genotypes, a multiallelic site, phased genotypes,
inherited and de novo variants, and two VEP-style CSQ transcripts per site.
The five-site `trio-truth.vcf` has five complete trios, four non-reference trios,
one Mendelian error/novel child singleton, one transmitted parental singleton,
and one untransmitted parental singleton. `calling.sam` has twelve reads,
eight supporting G and four supporting A at chr1:121; both bcftools callers
must call A>G, genotype 0/1. The general SAM has seventeen records, sixteen
mapped, with paired, unpaired, duplicate-marked and unmapped examples.

`sort-disordered.sam` has seven deliberately unsorted records spanning two
contigs, including mapped reads, unmapped reads that retain reference
coordinates, and one fully unplaced read. The sorting regression requires the
independently specified record order, a usable BAM index, and the expected
four-record chromosome-1 query. This prevents a skipped sort callback from
passing on input that was already ordered.

`upstream/1.16/` and `upstream/1.21/` are unchanged regression fixtures from
the official samtools/bcftools repository. `provenance/sources.lock.json`
records the exact upstream commit, raw URL, source path, SHA-256, byte length,
and licence for every copied file. Each directory includes its upstream
MIT/Expat licence. Tests with upstream sample identifiers are regression
fixtures; no provenance of an actual person's genome is asserted.

`manifest.json` binds all 98 fixture/licence files and the source lock. The
validation reports additionally bind the generator and its portability helper.

```sh
# First checkout: fetch the pinned upstream source cache and restore generated files.
python3 scripts/fetch-hts-test-data.py --fetch-sources --regenerate
python3 scripts/fetch-hts-test-data.py --verify
# Once the source cache exists, regeneration also works without a network:
python3 scripts/fetch-hts-test-data.py --regenerate
```

The compact logical-offset BGZF/GZI fixture represents 4 GiB + 64 KiB of
zeros followed by `TAILMARKER\n`, using about 8 MiB of files. Tests seek via its
index and read only four bytes. Do not decompress the whole fixture. A second
VCF produces BGZF blocks physically above 64 KiB, exercising virtual offsets
above 2^32 with only 6,000 variants. Other fixtures exercise a 6,000,000,000
aggregate depth and optical-duplicate coordinates above INT32_MAX. Their
construction and independent truths are documented in
`validation/hts/portability_fixtures.py`.

The two generated files `common/logical-offset.bgz` and
`common/logical-offset.bgz.gzi` are omitted from Git. Run
`--fetch-sources --regenerate` after a fresh checkout to materialize their exact
frozen bytes before verification. Regeneration rejects changed or extra existing
fixtures, and verifies generated bytes against the frozen manifest before writing.
Both files are included in the standalone release ZIPs. Their SHA-256 values
and sizes remain part of the committed manifest, so omission from Git does
not weaken fixture verification.
