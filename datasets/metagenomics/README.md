# Real metagenomics fixture

This compact fixture uses genuine Illumina paired sequencing reads from the
Zymo mock community: ENA run **ERR2984773**, study **PRJEB29504**, sample
**SAMEA5157164**. The study/sample/run records and original source webpage are
preserved under `provenance/sources/`. It is a numerical integration fixture,
not a benchmark of profiling accuracy or full database capacity.

The first 4,096 paired FASTQ records are copied byte-for-byte from the original
ENA files. Each mate is 151 bases. Downloading the pinned first 2 MiB of each
gzip file is sufficient for these complete records. These source fragments are
intentionally incomplete gzip members; only the selected complete records are
decoded. The distributed `.fastq.gz` fixtures are complete gzip files containing
exactly the distributed uncompressed FASTQ, with filename and timestamp omitted.

The database contains the first 1,000,000 bases, inclusive coordinates
1–1,000,000, from each of three pinned reference chromosomes:

| Reference | Accession | Species taxid |
| --- | --- | --- |
| E. coli K-12 MG1655 | NC_000913.3 | 562 |
| Salmonella enterica Typhimurium LT2 | NC_003197.2 | 28901 |
| Shigella flexneri 2a 301 | NC_004337.2 | 623 |

Reference sequence letters are unchanged; FASTA headers name the extracted
window, and line wrapping is fixed at 80 bases. The complete ancestor paths for
these species are transcribed from the preserved NCBI taxonomy XML into the
local `nodes.dmp` and `names.dmp`; no network taxonomy service is used at runtime.
The same first-window rule applies to all three chromosomes and does not select
sequences according to classification results. Shigella is a related reference
for testing shared ancestral assignments, not a claim that it is present in the
sequenced mock community. Most community organisms are absent from this limited
reference database. Reference strains also differ from some community strains.

This fixture was **reconstructed after the original working data were lost**.
The upstream sources and their SHA256 pins were recovered, but the previous
window-selection recipe and generated-data manifest were unavailable. These are
new, explicitly specified reference windows and new expected output identities;
no earlier validation results are reused for them.

`manifest.json` binds all fixture and provenance files, records read/reference
selection, observed native counts, source checksums, and the regeneration recipe.
Included database files and example outputs are produced by unchanged upstream
Kraken2 2.17.2 and Bracken 3.1 sources. Kraken2 uses one thread, default k=35 and
l=31, and explicitly disabled masking. Bracken's example model uses read length
151. Only unused native `opts.k2d` ABI padding is zeroed for reproducibility; all
declared database fields are preserved. Validation independently rebuilds the
database and model from source inputs in each execution target.

The unchanged native Bracken helper appends a malformed EOF record containing
uninitialized taxid bytes. Its unchanged Python model converter ignores that
record's empty hit list. The deterministic final `.kmer_distrib` model is
included; the malformed raw helper intermediate is discarded after conversion.
The validation suite separately checks and records this known upstream anomaly.

From the repository or standalone package root:

```sh
python3 scripts/fetch-metagenomics-test-data.py --verify
python3 scripts/fetch-metagenomics-test-data.py --fetch
python3 scripts/fetch-metagenomics-test-data.py --regenerate
```

Verification is offline. Fetching obtains missing sources or restores preserved
metadata snapshots; every source is checked for exact size and SHA256. Downloads
must honor the recorded HTTP range. Regeneration compiles pinned unchanged
native upstream programs in a temporary directory, rebuilds the fixture, and
compares every generated byte with the manifest. It requires Python 3.12+, a C++
compiler with OpenMP, make, Bash, and Perl, but no browser or WebAssembly runtime.
Only the explicit `--regenerate --update-manifest` command replaces committed
fixtures and expected identities. Cached pinned originals are included in release
packages, so packaged regeneration can run offline.
