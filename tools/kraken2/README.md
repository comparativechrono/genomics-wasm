# Kraken2

This package compiles the original Kraken2 classifier and local database helpers to WebAssembly. It pins official release tag `2.17.2`, commit `8c190b1b668825935dbf6dee5f969227dc8269bb`. That release's `VERSION` file still contains `2.17.1`; the original native wrapper and browser wrapper both report that upstream value. The release source and original MIT licence are included.

The five programs are `classify`, `build_db`, `estimate_capacity`, `dump_table` and `lookup_accession_numbers`. Their `.mjs` and `.wasm` files are under `dist/kraken2/`. [The runtime guide](../../runtime/KRAKEN2.md) describes the ordinary classification flags, inspection, local database construction and direct helper invocation. Browser execution needs neither SharedArrayBuffer nor cross-origin isolation.

Run `bash scripts/setup-emsdk.sh`, then `bash scripts/build-kraken2.sh all`. The build requires Python 3.12+, make, a C++ compiler with OpenMP, Perl and the pinned Emscripten 3.1.64. It produces an unchanged native build, a patched native build and the browser modules. Native launchers are `build/native/kraken2` and `build/patched-native/kraken2`; their sibling `kraken2-package/` directories contain the original installed Perl/shell wrappers and five compiled helpers. Native local builds use `kraken2-package/kraken2-build --build --db DIR --threads 1 --no-masking` with prepared reference sequences, sequence-to-taxid mapping and taxonomy files.

Kraken2 writes some database fields using native `size_t` and native struct layouts. We compile with Emscripten's `MEMORY64=2`: C++ retains the 64-bit native layout, then Binaryen lowers memory addressing to ordinary wasm32. Compile-time assertions check the options record, taxonomy node and integer widths. This avoids introducing a browser-only database format. The input database must use the usual little-endian 64-bit Kraken2 format and must fit alongside reads and outputs in the browser's memory.

The native baseline uses unchanged upstream source and OpenMP. The patched native and browser builds use upstream's existing serial implementation. The recorded patch rejects thread counts other than one, sets database loading to one reader, rejects daemon mode, and zero-initializes padding in the database options record. The original writer leaves that padding unspecified; these padding bytes are not settings. No minimizer, hash-table, taxonomy, classification or abundance algorithm is replaced. The browser wrapper translates command options and performs the same gzip decompression and capacity calculation as the original wrappers.

The initial scope is one database per classification, including paired reads, quality/confidence filters, reports, sequence outputs, translated searches against protein databases, inspection and local database preparation. Low-complexity masking, NCBI downloads, multi-database merging, daemon/FIFO operation and bzip2 transport are not exposed. Local builds require `--no-masking` and already prepared sequence/taxonomy files. Memory mapping uses the browser virtual filesystem and does not provide disk-backed access to a large desktop database.

The maximum compiled heap is 2 GiB. Inputs, output files, decompression and database copies also consume browser memory, so this is a small-database port, not a whole-database performance claim. Validation uses real sequencing reads and reference sequences, with independent native builds, native-to-browser and browser-to-native database exchange, exact classifications and report counts. The build manifest binds all source inputs, every module and the full native execution trees; archived sources can be restored from `dist/kraken2/sources/` for rebuilding.
