# Somatic caller validation

Run `node scripts/validate-somatic.mjs --tool somaticsniper --dataset hcc1395 --engine node` (or `--tool lofreq`). Browser engines are `chromium`, `firefox` and `webkit`; install the corresponding Playwright browsers first. Each invocation uses a fresh worker. Reports are written to `reports/somatic/<engine>/summary-<tool>-<dataset>.json`. A missing case, failed execution, missing output or unequal comparison makes the report fail. Ordinary static hosting is sufficient for these ports.

`cases.json` is the required case plan, also used by the release gate. It covers the real matched HCC1395 regional BAMs, parameter changes that alter actual output, repeated calls, and invalid inputs. Dataset provenance describes the coordinate rebasing and the limits of this small fixture. No reads or variants are synthesised for these integration cases. Published truth calls are not assumed to be detectable in every read subset.

Every successful biological case runs unchanged native code, patched native code and WebAssembly on the same input bytes. Dependent cases use each build's own preceding output. Reports bind the exact source/build assets, native helpers, runtime, validator, dataset manifest and file hashes. Input dependency hashes are recorded per execution. LoFreq's native somatic baseline runs the unchanged upstream Python script with its corresponding native executable. The browser scheduler must produce the same ordered command arguments as the native script's verbose execution log, and every intermediate and final VCF is compared. The 14-stage case exercises germline reporting, multiple-testing parameters, extra relaxed-call arguments, source-quality options and known-variant exclusion. Its exclusion list is a prior real callset used as a mechanical filter control, not a dbSNP dataset or accuracy benchmark; the comparator checks the exact allele-set complement and requires a real removal.

VCF comparison retains every fixed field, numeric string, sample order, phased genotype, INFO/FORMAT value, header definition and duplicate record. It does not normalise alleles, round QUAL or allow numeric error. Only unordered record/tag/header-metadata order, gzip wrapper metadata, LF/CRLF, valid run dates, declared executable names and working-directory provenance prefixes are normalised. REF bases and coordinates must agree with the bundled reference, required outputs must contain variants, and planned filters must have a measurable effect. LoFreq 2.1.5's intermediate `somatic_raw` VCFs contain the bare SOMATIC flag without its header declaration; only those explicitly identified outputs allow this upstream omission. The flag is still compared exactly, and all other undefined tags are rejected.

LoFreq indel-quality preparation is checked independently with a small standard-library BAM decoder: alignment order, read names, flags, coordinates, CIGAR, sequence, original qualities, every auxiliary tag and header field remain exact. BI/BD qualities must be present and valid on eligible reads; all other read content must match the original BAM. BAI structures and byte content are compared, virtual offsets must be within the BAM, and a mandatory nonempty regional call consumes the newly generated BAM/index. For these fixtures the three builds produce identical BGZF layout and BAI bytes.

The separate numerical primitive probe checks long-double exponent range and LoFreq's existing probability-to-PHRED behaviour, including errors raised inside its double-precision log-tail sum. An independent 90-digit Decimal oracle checks probability and log10 values: relative bounds are 3e-18 for the long-double exponent cases and 3e-15 for the upstream binary64 tail calculation; subnormals allow one quantum of the declared floating format. Range flags and integer PHRED values remain exact. Native x87 and WebAssembly binary128 have different subnormal ranges and significands. This narrowly scoped numerical policy does not apply to any VCF field. The max-probability clamp after an intermediate underflow deliberately preserves upstream behaviour.

SomaticSniper's unchanged upstream executable crashes on missing BAM files and can loop on a missing reference. Those two safety cases therefore run only patched native and WebAssembly code and require the documented clean error; successful biological cases always retain the unchanged native baseline. LoFreq parallel/resume restrictions are explicit browser-only errors. Other invalid-input cases require ordinary matching nonzero exits and diagnostics.

LoFreq's unchanged native default caller creates a hard-coded file in `/tmp`. That required case cannot pass in a host that forbids writing there; the validator records a failure rather than replacing the baseline or skipping the case. The full release gate requires passing Node and all three browser reports from a suitable host. Comparator mutant tests run with `python3 -m unittest discover -s tests -p test_somatic_compare.py`.
