# RNA analysis validation

Run `node scripts/validate-rna-analysis.mjs --tool all --engine node --dataset all` from the project root. Repeat with `chromium`, `firefox` and `webkit` after installing the pinned Playwright browsers. Browser validation serves the actual runtime and tool assets with cross-origin isolation, and starts a fresh worker for every command. A browser launch or execution failure fails the report; Node results are never substituted.

`cases.json` is the executable case plan shared with the release gate. Each case declares required executions, output files, comparisons, and any required option effect. Results are written to `reports/rna-analysis/<engine>/summary-<tool>-<dataset>.json`, with command output and comparison reports in case subdirectories. Separate tool processes can run without overwriting each other's summary. Reports bind the runtime, validation code and plan, native/patched binaries, all JavaScript/WASM assets, and the real dataset manifest/files by SHA-256. Missing cases, failed commands, missing outputs or a failed comparator prevent a passing report.

Every ordinary case runs the unchanged native program, the patched native program and its WebAssembly build. The native output first passes an independent structural contract. The other two outputs must agree with it exactly. Repeated WASM invocations are compared with the original native baseline. Error cases require diagnostics and matching nonzero exits; C `exit(-1)` is recorded as returned and also canonicalised to POSIX status 255. Unsupported thread counts are a separate port restriction, tested on patched-native and WASM only. Two mosdepth missing-file cases explicitly record an upstream failed-open SIGSEGV (or a normal nonzero exit if the platform handles it differently). For these two cases only, the port must return clean exit 2 and its specified missing-file diagnostic. Native crashes are disclosed as an upstream limitation, never described as successful rejection. No signal is permitted in patched-native or WASM execution.

The inputs are biological sequencing reads, real reference sequences and real annotations. Their preparation and provenance are verified offline before execution. These are tests of implementation equivalence, not evidence of biological accuracy.

Comparison policy:

- featureCounts: annotated feature identities, coordinates, lengths, all sample counts and every assignment-summary category must agree. Gene identities are checked against the independent GTF; coordinates must fit the reference. Empty all-zero counts fail ordinary cases. Gene/exon, paired fragment counting, both strands, overlapping features, multimappers, fractional counts, mapping-quality filtering, SAM/BAM input, multiple BAMs and threads 1/2/4 are exercised.
- StringTie: transcript and exon records, exon structure, strand, all attributes, gene/transcript identities, gene abundance and version must agree. Only row/attribute order and command path comments are ignored. Reference and generated identifiers are retained. Exons must lie inside their parent transcript and name the same gene. Merge must produce actual transcripts/exons, even though merged records have no coverage field. BAM/CRAM, guided and unguided assembly, estimation, both strand settings, coverage filtering, split-sample assembly and merging are exercised.
- mosdepth: decompressed coverage, distributions, region averages, threshold counts, quantised intervals and summary values must agree. Gzip wrapper bytes and CSI binary layout are not biological values; gzip checksums and the complete CSI structure are validated. Per-base intervals must tile each reported contig and their weighted depth must equal the summary. BED regions, windows, mapping-quality filtering, fast mode, fragment mode, thresholding, quantisation, omitted per-base output and BAM/CRAM input are exercised.

Numeric values use exact `Decimal` equality. There are no floating-point comparison tolerances. The independent mosdepth mean check allows the output format's two-decimal rounding, but native-to-WASM means still have to match exactly. High mapping-quality and coverage filter cases explicitly permit zero output and require a change from a positive baseline. Other option cases require a numerical or structural effect, not merely a changed command string.

`tests/test_rna_analysis_compare.py` includes counterexamples for renamed identifiers, altered counts and coverage, malformed/empty merge output, wrong exon parents, incomplete coverage, missing files, non-finite numbers and truncated CSI indexes.
