# Strelka2 validation

Run `node scripts/validate-strelka2.mjs --engine node` (or `chromium`, `firefox`, `webkit`). The complete case plan is in `cases.json`. Reports are written to `reports/strelka2/<engine>/summary-strelka2-all.json`; an incomplete or failed case plan cannot pass.

Each successful workflow runs the unchanged upstream Python 2.7 workflow and native binaries, the same workflow with the patched native binaries, and the browser workflow with the compiled WebAssembly helpers. Native configuration and execution use the pinned CPython 2.7.18 installation with bytecode writes disabled. The native oracle is `configureStrelkaSomaticWorkflow.py` followed by `runWorkflow.py -m local -j 1 -g 4`. No expected variant records are generated by the validation code.

The HCC1395/HCC1395BL fixture contains genuine matched tumour and normal reads in two documented regional reference segments. The Strelka-specific BAM dictionary includes precisely those reference contigs. Every input file, installed native helper and model, interpreter installation, source/build input, runtime module, and transitive validation script is hash-bound in the report. These small regional tests provide correctness evidence; they do not measure whole-genome browser performance or clinical accuracy.

VCF comparisons retain every allele, identifier, QUAL, FILTER, INFO and sample FORMAT value, numeric string, header definition, source/version/prior/model metadata, sample order and duplicate record count. Records and unordered INFO/FILTER fields may be reordered. REF alleles are checked against the actual reference. There is no numerical tolerance, allele normalisation or haplotype equivalence rule. Gzip is fully decompressed with CRC checks. Only valid run dates/times, specified executable names and working-directory prefixes are normalised. Unknown metadata remains significant.

Chromosome-depth rows are compared by chromosome name because upstream Python 2 writes this keyed table in dictionary order; every numeric string remains exact.

Statistics comparisons preserve all counters, XML fields and attributes; only the documented wall/user/system timing values and the matching `TotalHours` report line may vary. The 64-bit statistics regression starts from XML produced by each target's actual workflow, replaces its timing values with zero and its two counters with explicitly declared integers, then requires the independently specified exact sums. It is an arithmetic test, not simulated sequencing data.

Workflow command evidence comes from the unchanged native pyflow task log. Compiled helper arguments and translated file operations are compared with the runtime ledger after declared directory mapping. Shell reheader redirection followed by a temporary-file move is represented as the equivalent in-place reheader operation. Scheduler directory creation/removal and configure-time file inspections are checked for successful execution and file consistency, rather than compared with the native task scheduler's incidental ordering. Commands may be ordered differently when their dependencies permit it.

The WebAssembly ledger's inputs are verified against the actual input/model bytes and preceding stage outputs. Its returned files must match their recorded output hashes. Native retained depth and statistics files and the final compressed variant files are compared independently. For the single grouped segment used by this compact fixture, upstream moves the compressed segment VCF to the final VCF path; these are the same bytes. A separate tabix query consumes each target's own final VCF and index and compares actual returned records.

Option cases must demonstrate changes in native variant records (including scores, annotations and filters), not merely changes in command headers or filenames. Repeated workers must reproduce the original native baseline. Errors must return a nonzero status and the specified diagnostic; a signal is never treated as a valid result. The parallel bgzip restriction is explicitly port-only because unchanged native bgzip supports compression threads.

`tests/test_strelka2_compare.py` uses labelled structural fixtures and deliberate corruption to test the validators. Those fixtures are not biological integration evidence.
