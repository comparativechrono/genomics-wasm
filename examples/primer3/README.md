# Primer3 browser example

From the repository or extracted package root, run `python3 -m http.server 8000` and open <http://localhost:8000/examples/primer3/>. An ordinary static HTTPS host also works; no cross-origin isolation headers are required. Keep `examples/primer3`, `runtime`, `dist/primer3` and `datasets/primer3` at their supplied relative paths. Do not open `index.html` directly with `file://`.

Load the HBB example and run **Design primer pairs**. The input is the authentic 628-base human HBB transcript NM_000518.5, preserved in the fixture corpus with its source and checksum. The first three presets request paired primers, an internal oligo or target-constrained primers. Other presets run the original `oligotm`, `ntthal`, `ntdpal`, `amplicon3_core` and long-sequence Tm programs on exact segments of that transcript. The masker preset is explicitly separate: its tiny synthetic sequence and 4-mer table are a software demonstration, not genome-frequency data. Results are computational candidates; this example does not perform a whole-genome specificity search or establish experimental performance.

The program menu exposes the original bundled utilities. Primer design reads Boulder-IO records through standard input. Use **A loaded file** to preserve its exact bytes, or **Text entered below** to edit parameters. Terminate each record with a line containing `=`. Sequence masking requires separately supplied k-mer tables. The auxiliary programs have different command lines; consult the included upstream documentation before changing program. `primer3_core --about` prints program information; upstream `--help` prints usage to standard error and returns a nonzero status.

Uploaded folders retain their relative paths. Run arguments are a JSON array of strings, without the program name. There is no shell expansion, pipe or redirection. **Save standard output** places the returned bytes into the workspace, making them available to later commands; the generated Boulder-IO output can be used as input for another design run. Every stream can also be downloaded directly.

List explicit output files when they must be created afresh by a command. Their previous bytes are not mounted as inputs. Folder collection includes existing loaded and generated files as well as newly produced files; it is not a declaration that every file was regenerated. Earlier results remain available if a command fails, is cancelled, times out or omits an explicitly requested file. A Primer3 `PRIMER_ERROR` record is shown in the output and called out in the status; the original upstream exit status is retained.

Every run uses a fresh worker and WebAssembly instance. Cancel and the time limit terminate the worker. Inputs, outputs and computation stay in this browser; all program assets are local to the package. Reloading or clearing the workspace discards its files. Inputs and outputs are copied through browser memory, so this is intended for modest sequence sets.

Text previews are limited to the first 100,000 bytes. Downloads contain all original output bytes, including binary files collected from a folder.

The release gate runs `BROWSER=chromium node scripts/test-primer3-demo.mjs` and the Firefox and WebKit equivalents. It exercises the actual files served from this package, validates returned primers against the reference sequence, tests parameters, chaining, input/error handling, cancellation, timeout and exact downloads, and records SHA256 evidence for served assets. Separate native-equivalence tests establish the numerical validation.
